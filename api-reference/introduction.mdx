## Overview

APM Ninja provides OTLP (OpenTelemetry Protocol) endpoints for ingesting observability data from your applications. This section documents the public ingestion API for traces, metrics, and logs.

## Supported Protocols

APM Ninja supports two OTLP ingestion protocols:

- **OTLP/HTTP** - HTTP endpoints accepting protobuf-encoded OTLP payloads
- **OTLP/gRPC** - gRPC service accepting OTLP protobuf requests

Both protocols support the three core observability signals: traces, metrics, and logs.

## Authentication

All OTLP endpoints require API key authentication. Include your environment's API key in requests using one of these methods:

- `x-api-key: <your-api-key>` header
- `Authorization: Bearer <your-api-key>` header

You can find your API keys in the APM Ninja console under your environment settings.

## Endpoint Reference

This section documents:

- **POST /v1/traces** - OTLP HTTP trace ingestion
- **POST /v1/metrics** - OTLP HTTP metrics ingestion
- **POST /v1/logs** - OTLP HTTP logs ingestion
- **OTLP gRPC** - gRPC service for traces, metrics, and logs

<Note>
  This section covers only the standard OTLP endpoints. Alternative log ingestion endpoints under `/v2/ingest/logs/*` are documented separately.
</Note>

## Production Endpoint

All OTLP HTTP endpoints are available at:

```
https://otlp.apmninja.com
```

The OTLP gRPC service is available at:

```
otlp.apmninja.com:4317
```
